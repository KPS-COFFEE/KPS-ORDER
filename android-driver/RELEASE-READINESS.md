# Distribution blocked — release preparation

The owner-provided Android screenshots show that Google Play Protect blocked
installation of the original debug pilot, with a message about an unfamiliar
developer/application. They do not provide an exact malware classification or
installation error code. The blocked APK must not be redistributed as approved.

Original pilot APK SHA-256:
`57856a596edcecbe40e955599b2461e261db1ffcae9b25f7863bea9e241cb082`.

## Verified boundaries

- A successful Gradle build does not establish Play Protect acceptance.
- Release signing establishes update identity; it is not Google review,
  malware clearance, or a guarantee that an unfamiliar-app warning disappears.
- Do not disable Play Protect, lower target SDK, remove needed disclosure,
  change package identity repeatedly or rotate signers to evade classification.
- Actual compiled APK permissions and certificates are audited in CI. A strict
  allowlist excludes SMS, accessibility, notification-listener and package-install
  privileges. This is a permission audit, not a malware certification.

## Prepared release path

The release variant has debugging disabled and can produce an unsigned APK
and AAB for engineering review. They are not installation files for drivers.
The protected company signing configuration is supplied using
`KPS_DRIVER_KEYSTORE`, `KPS_DRIVER_STORE_PASSWORD`, `KPS_DRIVER_KEY_ALIAS` and
`KPS_DRIVER_KEY_PASSWORD`. Do not put those values or a keystore in source,
build reports, public workflow artifacts or chat. No temporary release key is
generated by the build. Preserve the chosen signing identity for all updates.

## Remaining external steps

1. Obtain the expanded Play Protect details from the affected device and
   record its Android version/model. Do not ask staff to disable protection.
2. Establish company-owned developer/distribution access and protected key
   custody. Select the distribution channel and satisfy its verification and
   policy requirements. Developer account sign-in/terms remain owner actions.
3. Validate privacy/location disclosure and the actual release on company
   devices. An emulator installation does not prove Play Protect acceptance.
4. If classification remains after review, use Google's supported Play Protect
   appeal or review route for the exact blocked package/certificate.
5. Publish a signed installation release only after the needed checks. Then
   pilot login, open shift, lock screen/WhatsApp, recovery and manager location.

No production deployment, new credentials, signing key, Google submission or
company-device installation is performed by this change.
