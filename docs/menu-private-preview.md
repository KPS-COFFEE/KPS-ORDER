# KPS private menu

This release adds a protected equivalent preview route within the existing KPS ORDER service. It does not change KPS-MENU, GitHub Pages, CNAME, the shared printed QR, production DNS, or the ordering homepage. The public activation state remains false; there is no public activation control in this private release.

- `/menu/preview`: owner or existing admin `products_manage` permission, fresh revocable server session; no-store/noindex, GPS explicitly disabled.
- `/menu/analytics`: owner only; preview/live datasets separate. Riyadh calendar ranges. Shared QR cannot identify physical scan location. Maps/social/review interactions are click counts only.
- `/menu/information`: owner editor using shared existing branch administration and first-party brand customer links. Admin branch edits still require `branches_manage` and the exact delegated branch scope.

The canonical catalog, product administration, options, approval provenance, server quotes and branch availability engine remain authoritative. The generic menu shows global status and defers all branch/city decisions to ordering. No menu-product table or infrastructure is added. Responses bypass catalog caching, with refresh on page visibility; static image previews reuse existing thumbnail infrastructure.

The existing public menu was inspected on 12 October 2026: 20 separate Google review links, one shared branch locator, WhatsApp 0550472662, Instagram @kps.coffe, Snapchat @Kps.cofee and TikTok @Kps.cofee. It displayed no numeric rating or review count. The additive import copies only missing customer information and runs once after initial canonical seed. Restarts never reset administrative edits. Approved Maps destinations come from the existing verified canonical branch registry, not generated coordinates. No paid Google API is used. Cached rating presentation requires a correct approved profile, timestamp and source; absent or mismatched ratings stay absent. A rating in a screenshot explicitly named SYNTHETIC is an isolated test fixture, not a real branch rating.

Menu handoffs issue random, 24-hour opaque references and preserve `source=menu_qr`; no names, phones, GPS or invented branch appear in the URL. Landing creates one order-start observation per handoff. Attributed order associations are written in the same transaction as order creation and remain idempotent. Counts for paid completed orders and gross order value use completion timestamps, exclude cancelled/unpaid orders and do not claim net revenue after refunds. Branch rate uses attributed orders created in the chosen range, not QR scans. Zero-denominator rates are null, not fabricated percentages.

The safe test journey creates an order through the customer API, collects cash through the authorized owner API and completes all preparation transitions before verifying menu analytics. All data remains synthetic and isolated.

Acceptance tests use PostgreSQL 18 and real Chromium, isolated UUID schemas and synthetic accounts/orders. No production product is disabled, no real test order is sent and no customer record is deleted. Existing full regression also runs. Screenshot artifact filenames distinguish private preview from synthetic rating examples and ordering handoff. Physical device/provider delivery and external Google target identity are separate from isolated browser acceptance.

Public activation remains an explicit owner decision after screenshot and protected preview review. Because menu.kps.sa is currently hosted on GitHub Pages, a later approved public release must attach the existing shared domain to the integrated experience with a default-off `NEW_MENU_ENABLED` switch and a tested immediate return to the unchanged legacy menu. This private release does not change hosting or DNS and does not pretend that deployment to a different host alone changes the public QR.
